# Firecrawl-стенд: сбор данных с сайтов в обход блокировок

МПЦ-сервер `firecrawl-stack` проксирует парсинг на удалённый стенд:
- **`scrape_url`** — антидетект-воркер (Camoufox) для тяжёлых/защищённых сайтов: маркетплейсы (Ozon, Wildberries, Avito, DNS, Мегамаркет), форумы и т.п.
- **`scrape_markdown`** — Firecrawl для обычных сайтов (быстрый markdown).

## Когда использовать
1. Пользователь просит «собери информацию с интернета» / «спарси» / «найди данные на сайте».
2. Обычный `webfetch`/открытие страницы вернул капчу, пустоту, ошибку, или сайт закрыт антиботом.

## Алгоритм
1. Сначала обычный `webfetch` на целевой URL.
2. Если контент получен — используй его.
3. Если капча/блок/пусто/ошибка — вызови **`scrape_markdown`** (обычный сайт), затем при необходимости **`scrape_url`** (маркетплейсы/защищённый сайт).
4. Разбери полученный текст/HTML под запрос пользователя и ответь по сути.

## Формат вызова тула
Имя тула в Kilo формируется как `<server>_<tool>`: `firecrawl-stack_scrape_url`, `firecrawl-stack_scrape_markdown`.

```text
scrape_url  {"url": "https://example.com/", "timeout": 60}
scrape_markdown {"url": "https://example.com/", "timeout": 60}
```

## Возможные ответы воркера и как себя вести
- `status: ok` + `title`/`text` — контент получен, парсируй.
- `status: captcha` — капча не далась; скажи пользователю и предложи повторить позже.
- `status: ip-blocked` — сайт режет IP (например, Ozon с домашнего адреса). Сообщи пользователю: нужен чистый/жилой прокси.
- `status: error` / `timeout` — сайт не отдал контент; попробуй `scrape_markdown` или повтори запрос через время.

## Ограничения
- Воркер — один браузер, запросы идут по очереди: **не запускай поиск параллельно/метлом-несколько сайтов разом**, выдержи паузу.
- Скрейп одного URL занимает ~5–30 секунд — не дублируй запросы.
- Не собирай персональные/закрытые данные без прав пользователя.
